Before you begin

This tutorial teaches the basics of Prolog using the interpreter in this repository. Everything shown here was run against it, so if a transcript says the answer is X = 7, that is what you will see.

Build it and start the toplevel:

$ make
$ ./prolog
C Prolog 1.0 -- a Prolog interpreter in C
Type help. for help, halt. to quit.

?-

The ?- is the prompt: it is Prolog asking you for a question. Type halt. to leave — including the full stop, which is how Prolog knows you have finished a sentence.

The programs in this tutorial are in tutorial/level1.pl. Load the file when you start:

$ ./prolog tutorial/level1.pl
Follow along
Read this page with a terminal open beside it. Prolog is quick to try things in, and the point of the language is hard to feel without watching it answer.

The idea in one page

Most languages are built from instructions: do this, then do that, return a value. Prolog is built from two other things — facts you state, and questions you ask. You describe what is true, and the system searches for a way to prove what you ask about.

A program is a set of relations. parent(esther, hannah) says that esther and hannah stand in the parent relation. It is not a function call and it returns nothing; it is a statement that this is so.

The consequence takes some getting used to: a relation can be used in any direction. One definition of parent/2 answers all of these:

  • Is esther a parent of hannah? — ask parent(esther, hannah)
  • Who are esther's children? — ask parent(esther, Child)
  • Whose parent is hannah? — ask parent(Who, lars)
  • Which parent-child pairs exist at all? — ask parent(P, C)

You never wrote three functions for that. You wrote facts, and asked different questions about them.

Facts

A fact is a relation name and its arguments, ended by a full stop. Here is the start of tutorial/level1.pl:

parent(esther, hannah).
parent(esther, isaac).
parent(hannah, lars).
parent(hannah, maja).
parent(isaac, nils).

female(esther).
female(hannah).
female(maja).

male(isaac).
male(lars).
male(nils).

Three rules of spelling matter from the start:

Written asMeans
esther, hannah, parentAn atom: a name that stands for itself. It begins with a lower-case letter.
Child, Who, XA variable: a blank to be filled in. It begins with a capital letter or an underscore.
parent(esther, hannah)A relation applied to arguments. No space before the bracket.
.Ends every fact, rule and question. Forgetting it is the most common beginner error.

parent/2 is how a relation is named when you talk about it: the name, then how many arguments it takes. parent/2 and parent/3 would be different relations entirely.

Order matters, and it is the order you wrote
Prolog tries facts and rules from the top of the file downwards. That is not an implementation detail you can ignore — it decides the order of answers, and sometimes whether you get any.

Asking questions

With the file loaded, ask whether something is true. A question with no variables gets a yes or no:

?- parent(hannah, lars).
true 

?- parent(hannah, esther).
false.

true means Prolog proved it from what you gave it. false means it could not — which is not quite the same as "this is false in the world". Prolog only knows what is in the file. Nothing there says hannah is a parent of esther, so the answer is no.

Notice the space after the first true, where the second answer ends in a full stop. The space means Prolog is waiting: it has found one proof but there may be more, and it wants to know whether to look. Press return to stop, or ; and return to search on.

That is more interesting with a variable in the question. A variable asks Prolog to find values that make the question true:

?- parent(esther, C).
C = hannah ;
C = isaac.

The first answer came back with a space after it; typing ; asked for another; after C = isaac there was a full stop, because Prolog could see there were no more clauses left to try.

Keep asking past the last answer and you get false — meaning "no further proof", not "the previous answers were wrong":

?- parent(X, lars).
X = hannah ;
false.
Try these
parent(P, C) on its own — every pair in the database, one ; at a time. Then male(X), then female(esther).

A variable you do not care about can be written _, the anonymous variable. parent(esther, _) asks whether esther has any child at all without asking who.

Variables and unification

The single most important thing to understand about Prolog is what = does, because it is not assignment. X = hannah does not store hannah in X. It asks: can these two things be made the same?

?- X = hannah.
X = hannah.

They can, by letting X stand for hannah. That is unification: matching two terms, filling in variables as needed to make them identical. It works on structure, in both directions at once:

?- f(a, B) = f(A, b).
B = b,
A = a.

Prolog lined the two terms up: same name f, same number of arguments, then argument by argument. a had to match A, so A stands for a; B had to match b, so B stands for b.

When two terms cannot be made the same, unification simply fails:

?- f(a) = g(a).
false.

?- f(a, b) = f(a).
false.

This is why a variable in a question works the way it does. Asking parent(esther, C) means: find a fact that unifies with this pattern. parent(esther, hannah) does, with C standing for hannah.

A variable is filled in once, but only until Prolog backtracks
Within one proof a variable that has been given a value keeps it — there is no reassignment. When Prolog gives up on a line of reasoning and tries another, the values it filled in along the way are undone. That undoing is what lets the next answer be found.

Rules

A rule says that something is true if something else is. The :- is the "if", and the comma is "and":

mother(M, C) :- parent(M, C), female(M).

Read it aloud: M is the mother of C if M is a parent of C, and M is female. The part before :- is the head, the part after is the body.

?- mother(M, lars).
M = hannah

Rules may use other rules, and may use themselves — which comes later on this page. A grandparent is a parent of a parent:

grandparent(G, C) :- parent(G, P), parent(P, C).

The variable P appears twice in the body and nowhere in the head. That is what ties the two goals together: the same person must be both esther's child and lars's parent. A variable that appears only inside the body is local to the rule.

?- grandparent(G, lars).
G = esther 

?- grandparent(esther, C).
C = lars ;
C = maja ;
C = nils.

One more, which needs a way of saying "different":

sibling(A, B) :- parent(P, A), parent(P, B), A \== B.

A \== B succeeds when A and B are not the same term. Without it, everybody would be their own sibling, since parent(hannah, lars) matches both goals at once.

  1. Write grandmother/2 using grandparent/2 and female/1.

  2. Write father_of_a_son/1: someone who is the father of a male child.

Solutions
grandmother(G, C) :- grandparent(G, C), female(G).

father_of_a_son(F) :- father(F, C), male(C).

Test them with grandmother(G, lars). and father_of_a_son(X). — the second answers X = isaac.

How Prolog answers

It is worth being precise about what happens when you ask a question, because everything else follows from it. Take grandparent(esther, C).

Step by step:

  1. The question grandparent(esther, C) matches the head of the rule, so it is replaced by the rule's body: parent(esther, P), parent(P, C).

  2. Prolog takes the leftmost goal first. parent(esther, P) matches the first fact about esther, so P stands for hannah. It remembers that another fact could have matched.

  3. Now the second goal, with P filled in: parent(hannah, C). That matches, C stands for lars, and there are no goals left — so C = lars is an answer.

  4. Asked for more, Prolog goes back to its most recent choice. parent(hannah, C) had another match: C = maja.

  5. Out of matches there, it goes further back, to the choice it left at parent(esther, P): P stands for isaac instead. The undoing matters here — C is a blank again before the search continues.

  6. parent(isaac, C) gives C = nils. Nothing is left to try anywhere, so the next request for an answer would be false.

That is the whole engine: try goals left to right, try clauses top to bottom, and on failure go back to the most recent choice and take the next option. It is called backtracking, and it is doing the work that loops and conditionals do in other languages.

Recursion

grandparent/2 reaches exactly two generations. For any distance, a rule has to refer to itself. The pattern is always the same: one clause that stops, and one that takes a step and recurses.

ancestor(A, D) :- parent(A, D).
ancestor(A, D) :- parent(A, X), ancestor(X, D).

The first clause is the base case: a parent is an ancestor. The second says A is an ancestor of D if A is a parent of somebody who is an ancestor of D.

?- ancestor(esther, D).
D = hannah ;
D = isaac ;
D = lars ;
D = maja ;
D = nils

The order is worth reading twice. Both of esther's children come first, because the base-case clause is tried before the recursive one. Only when those are exhausted does Prolog take a step down and start again.

The mistake everybody makes once

Write the recursive call first and you get a program that never answers:

ancestor(A, D) :- ancestor(A, X), parent(X, D).   % do not do this
ancestor(A, D) :- parent(A, D).

To prove ancestor(esther, D), Prolog must first prove ancestor(esther, X) — which sends it to the same clause, which asks the same thing again. It never reaches a fact. The interpreter will sit there consuming memory until you interrupt it with Ctrl-C.

The cure is the discipline above: make progress before you recurse. In the working version the recursive clause consumes a parent step first, so each call is asked about someone further down the tree, and the questions eventually run out.

  1. Using ancestor/2, ask who all of lars's ancestors are. Which direction of the relation is that?

  2. Write descendant/2 in terms of ancestor/2.

Solutions
?- ancestor(A, lars).
A = hannah ;
A = esther 

descendant(D, A) :- ancestor(A, D).

The first is the same relation read the other way round — no new code needed, which is the pay-off for describing relations rather than writing functions.

Arithmetic

Numbers need one special word, because of what = really means. Unification matches structure, so this succeeds without computing anything:

?- X = 3 + 4.
X = 3+4.

X now stands for the term 3+4 — a compound term with two arguments, exactly like parent(esther, hannah) has two. To evaluate it, ask for that specifically with is:

?- X is 3 + 4.
X = 7.

is evaluates the expression on its right and unifies the result with the left. Everything in the expression must already have a value:

?- X is Y + 1.
ERROR: Arguments are not sufficiently instantiated

This is the one place where Prolog stops being able to run in several directions: is computes forwards only. Comparisons work the same way, evaluating both sides:

WrittenTrue when
X =:= Ythe two expressions have equal values (2 + 2 =:= 4)
X =\= Ytheir values differ
X < Yless than; also >, =<, >=
X = Ythe two terms unify — no arithmetic at all
X == Ythe two terms are already identical, without unifying them

Note =< for "less than or equal", not <=. In the tutorial file:

age_in(Person, Year, Age) :-
    born(Person, Born),
    Age is Year - Born.

?- age_in(hannah, 2026, A).
A = 54.

  1. Write age_gap/3, true when the gap between two people's birth years is a given number of years. Which arguments have to be bound when you call it?

Solution
age_gap(A, B, Gap) :-
    born(A, YearA),
    born(B, YearB),
    Gap is YearB - YearA.

?- age_gap(hannah, lars, G).
G = 26.

A and B must be bound to people, because is needs both years before it can subtract. Gap is the one argument that may be a variable.

When things go wrong

Four messages account for most of what a beginner sees.

MessageWhat happened
Unknown procedure: parnet/2A name Prolog has never heard of — nearly always a typo, or a file that was not loaded. Check the spelling and the argument count.
Arguments are not sufficiently instantiatedSomething needed a value and got a blank. Usually is with an unbound variable on the right.
Syntax error: operator expectedMost often a missing full stop at the end of a line, or an unclosed bracket or quote.
false.Not an error at all: Prolog could not prove what you asked. Check your facts, and check the argument order — parent(lars, hannah) is a different claim from parent(hannah, lars).
A useful habit
When a query surprises you, ask a simpler one. If grandparent(esther, C) gives nothing, try parent(esther, P) and then parent(hannah, C) by hand. The goal that fails first is where the mistake is.

Exercises

These use tutorial/level1.pl and nothing beyond this page. Try them in the toplevel before opening the solutions.

  1. How many children does esther have? Ask a question that shows them, one at a time.

  2. Write parent_of_two/1: someone with at least two different children.

  3. Write aunt_or_uncle/2, true when the first person is a sibling of the second person's parent.

  4. Write same_generation/2 for people who share a parent, then say why this is not the same relation as sibling/2.

  5. Without running it, predict the answers to sibling(X, Y) and their order. Then check.

  6. Write eldest_child/2: a child of a given person who was born before all their other children. This one is harder than it looks — say what makes it awkward with only what you know so far.

Solutions

1. parent(esther, C). and press ; — two children, hannah and isaac.

% 2.
parent_of_two(P) :- parent(P, A), parent(P, B), A \== B.

% 3.
aunt_or_uncle(A, C) :- parent(P, C), sibling(A, P).

% 4.
same_generation(A, B) :- parent(P, A), parent(P, B).

2. answers esther twice and hannah twice, for the same reason as exercise 5: the two children can be picked in either order. Getting each answer once needs setof/3, in Level 2.

4. same_generation/2 has no A \== B, so it also says everybody shares a generation with themselves. sibling/2 excludes that.

5. Four answers, in this order:

?- sibling(X, Y).
X = hannah,
Y = isaac ;
X = isaac,
Y = hannah ;
X = lars,
Y = maja ;
X = maja,
Y = lars

Each answer binds two variables, and the toplevel prints one binding per line.

Two things to notice. Esther's children are siblings too, which is easy to forget when you are thinking about the younger pair. And every pair comes out twice, once in each order, because the rule's two goals can match the two children either way round — nothing says the first argument has to come first in the file.

6. The awkward part is "before all their other children": that is a claim about every other child, and so far you can only state claims about particular ones. It needs negation or a way of gathering all the answers at once — both of which are Level 2. A half-answer with what you have:

% true when C is a child of P and no *known* younger sibling was found first --
% correct only if you check every candidate yourself
older_child(P, C, Other) :-
    parent(P, C), parent(P, Other), C \== Other,
    born(C, Y1), born(Other, Y2), Y1 < Y2.

Where this goes next

You now have the whole model: facts, rules, unification, and a search that backtracks. Everything else in Prolog is built from those four things.

Level 2 takes on the parts that make it practical:

  • Lists — what they really are, and the patterns for walking and building them.
  • Collecting answers — findall/3, setof/3 and aggregate_all/3, for the questions that ask about all the solutions at once. That includes the eldest-child exercise above, which is solved there.

Level 3 will turn to controlling the search — negation, the cut, your own data structures and the grammar notation.
